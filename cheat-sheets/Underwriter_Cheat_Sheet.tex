{\huge{\bf \textbf{\texttt{Underwriter} Class Cheat Sheet}}}

\raggedright
\texttt{\m Underwriter($*$, name='Rory', databases=None, update=cfg, log2=cfg, debug=False)}${}^{[1]}$ \\

The \texttt{Underwriter} manages the creation of \texttt{Aggregate}, \texttt{Severity}, \texttt{Portfolio}, and \texttt{Distortion} objects, maintains a \texttt{knowledge} base of named DecL declarations keyed by \texttt{(kind, name)}, and provides the interface to the Lark-based DecL parser. The convenience method \texttt{\m build}${}^{[2]}$ is the primary entry point; \texttt{uw(program)} delegates to it.
The following tables show all \texttt{\m methods}, and fields or properties (used interchangeably). Comments elucidate the meaning of more obscure entries.

\bigskip \raggedright
{\bf Notes:}

[1]: Arguments are \textbf{keyword-only} (leading \texttt{$*$}): use \texttt{databases='test\_suite'}, not \texttt{Underwriter('test\_suite')}. \texttt{update} and \texttt{log2} default to the \texttt{[build]} section of \texttt{config.toml}.

[2]: Also exported as \texttt{from aggregate import build}. The module-level \texttt{build} pre-loads \texttt{build.databases} (\texttt{test\_suite}) whereas a bare \texttt{Underwriter()} starts empty. \texttt{build} returns one object, \texttt{build\_many} a list.

[3]: \texttt{aggregate/agg/test\_suite.agg} (categories A--O) is now exercised by \texttt{uv run pytest}, not by an \texttt{Underwriter} method.

\texttt{kind} $\in$ \{\texttt{sev}, \texttt{agg}, \texttt{port}, \texttt{distortion}\}; database search path cwd $\to$ \texttt{user\_dir} $\to$ \texttt{default\_dir}.
